# 看板

一个存在本地 JSON 文件里的看板。没有账号、没有服务端、没有同步，装完左栏多一个「看板」标签，
点开就是一块能拖动的板。

卡片是同一份文档：面板里拖的、对话里让智能体建的，都是同一张卡。没有缓存层，也就没有
「面板显示的和实际不一样」这件事。

## 它是什么

```
待办 ──── 卡片 · 卡片 · 卡片
进行中 ── 卡片
已完成 ── 卡片
```

只有一块板，没有项目切换、没有名字要起：打开就是它。整块板装在一个 JSON 文件里，默认
`~/.dsh/kanban/kanban.json`。整个文件就是这个插件的数据库：删掉它等于重置，复制它等于备份，
`git diff` 能看出每一次改动。

## 用起来

| 动作 | 怎么做 |
| --- | --- |
| 新建卡片 | 列头的 `+`，卡片加到这一列的末尾 |
| 改卡片 | 点开卡片，标题、描述、优先级、开始与截止日期都在右侧抽屉里，失焦即存 |
| 关掉抽屉 | `Esc`，或点抽屉外的蒙层 |
| 选日期 | 点「开始」或「截止」整行任意位置都会弹出日期选择框 |
| 移动卡片 | 拖到别的列，或拖到同列的另一位置 |
| 排序列 | 按住列头左侧的圆形标记拖动，松手落在两列之间 |
| 新建列 | 右上角的「新建列」 |
| 删列 | 列菜单里点「删除列」，再点一次确认 |

没有「保存」按钮：看板没有草稿态，一个保存按钮只会被忘记按。删除是两步的：第一次点只是
换成确认块，真正删除要再点一次，误点不会掉数据。

「待办」和「已完成」是系统内置的两列，也就是一张卡从「还没开始」走到「做完了」的两端。它们
可以改名——叫「需求池」「上线」都行——但不能删除，删掉板子就没有地方接住刚建的卡和刚做完的卡。
真去删的时候，列菜单会就地说明原因，而不是把这一项置灰让你猜。其他列只有在空了之后才能删：
里面还有卡片时点「删除列」会告诉你还剩几张，移走或删掉再点一次就行。

列的顺序是你摆的，不是固定的：按住列头左边那个圆形标记拖动，拖到哪一列的左半边就插在它前面，
右半边就插在它后面。拖起来的那一列会变淡留在原地，落点会亮起一条边——松手之前就看得到结果。
拖拽的把手只做在标记上，列名和旁边的按钮仍然是正常的点击目标。

卡片有开始和截止两个日期，卡面上合成一条 `11月20日 → 12月1日` 的窗口；只有一头时显示那一头。

优先级用卡片左侧的颜色条区分：紧急红、高橙、中黄、低蓝，右上角同时写着「紧急 / 高 / 中 / 低」。
颜色只是让人一眼扫出轻重，认字的人不靠它也能读。做完的卡片会沉回列里：没有边框、没有底色差，
标题降到最弱的一级灰，事情还记着，但不再催人。列头左边有个状态标记，空心圆是进行中的列，
打勾的绿圆是收尾的那一列——列名改过之后，这个标记仍然说得出它是什么。

每张卡片自带一份变更记录，从创建那一刻开始：改标题、改描述、换优先级、动日期、换列，都会
记下「从什么变成什么」和发生时间。只记真正的变化——原样保存一次不会多出一条。记录跟着卡片
走，删卡就一起没了，也不会单独出现在别处。

## 配色从哪来

板子没有自己的调色盘：底色、文字、边框、圆角、字体全部取自 DSH 的设计变量，所以切主题时
它跟着变，不会变成一块黑色的孤岛。

三个表面是同一条明度阶梯上的三级：页面最平，列比页面亮一点点，卡片再亮一档——像一块板子上
铺了一层、再在槽里放上卡片。深色下如果让列比页面更暗，整块板会像被挖了三个洞，所以那里
是往上走而不是往下沉；浅色下同一套关系仍然成立——浅灰的槽、白色的卡片。每一级都是从页面色
向文字色混出来的，一个公式同时服务两个主题，也不会偏蓝。做完的卡片退回槽里，等于从这条阶梯上退场。

## 对话里也能用

插件注册了三个工具，面板和对话读写同一份文档：

| 工具 | 作用 |
| --- | --- |
| `board_view` | 读列和卡片 |
| `board_add_card` | 新建卡片 |
| `board_move_card` | 移动卡片、调整位置 |

所以「把今天这几件事记到看板待办」是一句能落地的话，而不是一句要自己手动抄的话。工具不用先
问「哪块板」——面板上只有一块，`board_view` 直接返回它的列，建卡和移卡只要列 id 和卡片 id。

## 存哪、怎么改

默认 `~/.dsh/kanban/kanban.json`，在插件配置里把 `dataFile` 指向别处即可搬家。

写入是「读整份 → 改 → 原子替换」，所以中途崩掉留下的是上一版完整文档，不是半块板。并发
写入串成一条队列，两次同时改动不会互相覆盖。

文件坏掉不会让标签白屏：坏文件被改名成 `board.json.corrupt-<时间戳>` 留在原地，看板从一张
新的空板继续。你的东西还在磁盘上，只是这一版不认它。

## 什么是故意没有的

不做多用户、权限、评论、全板动态、时间记录（工时）、甘特图、日历、搜索、GitHub 集成、通知、附件。
这些功能每一个都需要一块它自己的存储和一堆它自己的界面，而这块板的全部价值在于小到能整份
读完。

全板动态指的是那种横跨整块板的时间线：谁在什么时候动了哪张卡。它要有意义就得先有「谁」，
而这块板没有账号，流水里每一行都会是同一个人；剩下的就只有一张按时间排的全板日志，读不完。
变更记录是每张卡片自己的一小段，点开才看，不是那样一条流。

需要真的多人协作时，用 Plane 或 Kaneo；它们本来就是为那个场景写的。
