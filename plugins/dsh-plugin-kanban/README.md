# 看板

一个存在本地 JSON 文件里的看板。没有账号、没有服务端、没有同步，装完左栏多一个「看板」标签，
点开就是一块能拖动的板。

卡片是同一份文档：面板里拖的、对话里让智能体建的，都是同一张卡。没有缓存层，也就没有
「面板显示的和实际不一样」这件事。

## 它是什么

```
待规划 ── 卡片 · 卡片 · 卡片
待办 ──── 卡片
进行中 ── 卡片
待验收 ── 卡片
已完成 ── 卡片
```

只有一块板，没有项目切换、没有名字要起：打开就是它。整块板装在一个 JSON 文件里，默认
`~/.dsh/kanban/kanban.json`。整个文件就是这个插件的数据库：删掉它等于重置，复制它等于备份，
`git diff` 能看出每一次改动。

## 用起来

| 动作 | 怎么做 |
| --- | --- |
| 新建卡片 | 列头的 `+`，卡片加到这一列的末尾 |
| 改卡片 | 点开卡片，标题、描述、工作区、状态、优先级、开始与截止日期都在右侧抽屉里，失焦即存 |
| 关掉抽屉 | `Esc`，或点抽屉外的蒙层 |
| 选日期 | 点「开始」或「截止」整行任意位置都会展开日历，点另一处即收起 |
| 移动卡片 | 拖到别的列，或拖到同列的另一位置 |
| 等人接手 | 抽屉底部点「人工介入」，卡片挂上琥珀色的环 |
| 让它跑起来 | 抽屉里选好工作区，点底部「开始执行」，看板为这张卡片新开一个会话 |

没有「保存」按钮：看板没有草稿态，一个保存按钮只会被忘记按。删除是抽屉底部那个垃圾桶图标，
两步：先点图标换成确认块，再点「删除」才真的删，误点不会掉数据。

列是固定的五列，跟着工作本身走，不是一块可以随便捏的板：

```
待规划 → 待办 → 进行中 → 待验收 → 已完成
```

事情先落在待规划里，决定要做了挪到待办，动手是进行中，做完等验收是待验收，验过才是已完成。
列的顺序、名字、数量都在代码里定义，面板上没有改名、加列、删列、调顺序的入口——要改这一串，
改的是这个插件，而不是某一块板。

「等人」不是一段路，是一种状态：任何一列里的卡片都可以被标记为需要人工介入，卡片上会多一个
「需人工」标签、外面加一圈琥珀色的环。它和卡片停在哪一列无关——待办里等一个决定、进行中里等
一个账号、待验收里等一次确认，都是同一件事，所以不占单独一列。

只有「已完成」是完成列：卡片在那里才渲染成做完的样子。这个身份也写在代码里，不是一个开关。

卡片有开始和截止两个日期，卡面上合成一条 `11月20日 → 12月1日` 的窗口；只有一头时显示那一头。

优先级用卡片左侧的颜色条区分：紧急红、高橙、中黄、低蓝，右上角同时写着「紧急 / 高 / 中 / 低」。
颜色只是让人一眼扫出轻重，认字的人不靠它也能读。做完的卡片会沉回列里：没有边框、没有底色差，
标题降到最弱的一级灰，事情还记着，但不再催人。

每列列头左边有一个自己的标记，一眼扫过去就知道这块板走到哪了：待规划是虚线环（还没定下来），
待办是空心圆（排上了），进行中是缺口环（转动中），待验收是眼睛（要有人看），已完成是打勾的
圆。五个标记都是 Lucide 的圆环族，形状成套，不是五张借来的图片；颜色统一跟随列头文字，
完成与否只由形状区分。

界面上的图标全部取自 [Lucide](https://lucide.dev)，形状和 24×24 的坐标都照原样，没有自己画的
替代品；只有描边比 Lucide 默认的 2 细一点，13px 文字旁边才不会显得发黑。

每张卡片自带一份变更记录，从创建那一刻开始：改标题、改描述、换优先级、动日期、换列、标记
人工介入、换工作区，都会记下「从什么变成什么」和发生时间。只记真正的变化——原样保存一次
不会多出一条。记录跟着卡片走，删卡就一起没了，也不会单独出现在别处。

## 配色从哪来

板子没有自己的调色盘：底色、文字、边框、圆角、字体全部取自 DSH 的设计变量，所以切主题时
它跟着变，不会变成一块黑色的孤岛。

三个表面是同一条明度阶梯上的三级：页面最平，列比页面亮一点点，卡片再亮一档——像一块板子上
铺了一层、再在槽里放上卡片。深色下如果让列比页面更暗，整块板会像被挖了三个洞，所以那里
是往上走而不是往下沉；浅色下同一套关系仍然成立——浅灰的槽、白色的卡片。每一级都是从页面色
向文字色混出来的，一个公式同时服务两个主题，也不会偏蓝。做完的卡片退回槽里，等于从这条阶梯上退场。

## 对话里也能用

插件注册了三个工具，面板和对话读写同一份文档：

| 工具 | 作用 |
| --- | --- |
| `board_view` | 读列和卡片 |
| `board_add_card` | 新建卡片 |
| `board_move_card` | 移动卡片、调整位置 |

所以「把今天这几件事记到看板待办」是一句能落地的话，而不是一句要自己手动抄的话。工具不用先
问「哪块板」——面板上只有一块，`board_view` 直接返回它的列，建卡和移卡只要列 id 和卡片 id。

## 让它跑起来

卡片不只是一条备忘，它可以是活干的入口。抽屉里选好工作区，点「开始执行」：

1. 卡片移到「进行中」，卡面出现「执行中」标签和一个转动的环；
2. 看板在那个工作区里新开一个会话，标题就是这张卡片；
3. 会话读到的是卡片的描述，做完了会自己把卡片送到「待验收」。

这一路不需要人盯：会话跑完，卡片自己往前走；会话报错，卡片退回「待办」、标上需要人工介入、
记下这次失败的原因。所以抽屉里那张「上次执行」的红字，是上一次尝试留下的，不是这次的开头。

跑起来以后卡片是锁住的：执行中不能再点一次，工作区也不能中途改——改了等于骗人，那次会话
还在老地方跑。要看它干到哪了，点「打开会话」直接跳进那个对话。

跑过一次的卡片会记住那个会话，底部的按钮从此就是「打开会话」——接着聊也好、追加要求也好，
都在那个对话里说。看板不会再给同一张卡片开第二个会话：一件事一个会话，重启一个就等于把上下文丢了。
那个会话要是被你归档了，看板会先把它从归档里捞回来再打开，不然它没有能承载的窗口。

会话是新建的，不在当前对话里跑：一张卡片一件事，一个会话一段上下文，混在一起谁也说不清
哪句是对哪张卡说的。工作区决定它在哪个目录里动手，也决定它看到哪份代码——所以下拉框里
列的是你挂载过的工作区，不是磁盘上的目录。

没有 worktree 隔离：会话就在工作区本身里改文件，一个工作区同时跑两张卡，它们会踩到一起。
这条是有意留白的，真需要并行时给它们配两个工作区。

## 存哪、怎么改

默认 `~/.dsh/kanban/kanban.json`，在插件配置里把 `dataFile` 指向别处即可搬家。

写入是「读整份 → 改 → 原子替换」，所以中途崩掉留下的是上一版完整文档，不是半块板。并发
写入串成一条队列，两次同时改动不会互相覆盖。

文件坏掉不会让标签白屏：坏文件被改名成 `board.json.corrupt-<时间戳>` 留在原地，看板从一张
新的空板继续。你的东西还在磁盘上，只是这一版不认它。

## 什么是故意没有的

不做多用户、权限、评论、全板动态、时间记录（工时）、甘特图、日历、搜索、GitHub 集成、通知、附件。
这些功能每一个都需要一块它自己的存储和一堆它自己的界面，而这块板的全部价值在于小到能整份
读完。

列也不可配置：没有改名、加列、删列、调顺序，也没有给列上色。五列是这条工作流的形状，能改的
话它就会在每台机器上长成不同的样子，而「待验收」到底在第几列就不再是一句能说清的话。

全板动态指的是那种横跨整块板的时间线：谁在什么时候动了哪张卡。它要有意义就得先有「谁」，
而这块板没有账号，流水里每一行都会是同一个人；剩下的就只有一张按时间排的全板日志，读不完。
变更记录是每张卡片自己的一小段，点开才看，不是那样一条流。

需要真的多人协作时，用 Plane 或 Kaneo；它们本来就是为那个场景写的。
