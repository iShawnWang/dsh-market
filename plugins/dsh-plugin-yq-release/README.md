# YQ-前端发布

一句话把分支发到测试环境：`把 feat/h5-活动弹屏 发到测试`。插件按你给过的链路查分支、合并到目标分支，
然后发布 Spug 前端或触发小程序构建，最后给一张结果卡片。

它把平时手工敲的四步（`branch-info` → `merge` → `spug deploy-and-watch` / 小程序构建 → 记账）收进一个工具，
并保留了原来那些必须踩过才知道的规矩。

## 它做什么

```
选项目/分支 → [可选]合并 → 发布 → 结果卡片 + 记一条账
```

## 链路从哪来

插件**不自带任何项目表**。它认识的每条链路都来自两个地方，且都是你自己给过的：

1. `Config` 里的 `projects`（手写的登记表，见「配置」一节）；
2. **发布记录**——每次发布都会把当时的链路快照写进账本，下次据此重建。

所以第一次发某个项目时要把它说全，跑完就记住了：

```
把 feat/h5-活动弹屏 发到 test，方式是 spug，应用 new_h5
```

也就是 `project` + `targetBranch` + `provider` + `app` 四件事。之后同样的项目只给分支名就够。

从记录里学到的链路一律**只能点名**，不会从分支名推断：账本记的是「发过什么」，不是
「哪些分支前缀该选中它」。分支名里认不出可靠中缀时猜错就是发错环境，所以插件不猜。

点名的方式有几种，都等价：

- 对话里说「把 feat/xxx 发到老虎机」→ 工具收到 `project: "tiger"`
- 直接指定链路 `chain: "yeqiao-mobile/h5"` 或 `chain: "h5"`
- 项目 id、项目名都认，从记录里学到的项目也可以

## 三种用法

对话里说一句话就行，插件注册了三个工具：

| 工具 | 作用 |
| --- | --- |
| `yq_release` | 执行发布。合并、发布、等结果，返回一张卡片 |
| `yq_release_plan` | 只预览会做什么，没有任何副作用 |
| `yq_release_history` | 读历史记录，最新在前 |

或者点侧边栏的 **YQ-前端发布** 标签：最上面可折叠的「配置」（地址 + 凭据，填完失焦即存），
下面依次是链路清单和历史记录。配置区默认收起，折叠标题右侧会显示「已完成 x/6」。
面板**不发起发布**——发布动作留在对话里，面板负责让人看清现在是什么状态。

## 六条规矩

这些是插件写死的，不是建议：

1. **合并冲突绝不自动解决。** 一检测到 `has_conflicts` 或 `cannot_be_merged` 就停，列出 MR 地址，
   等人工处理。插件里没有「尝试解决冲突」或「强制合并」的代码路径。
2. **commit hash 才是主键。** Spug 请求名固定为 `<目标分支>#<7位短commit>`，建完请求按 name
   回查拿 request id；小程序以构建日志里 `Build successful` 的 Commit hash 为准，
   不认 `trigger_build` 的返回值（那是触发瞬间的旧 HEAD）。
3. **构建机连不上就报 blocked。** 探活三次（退避 1s / 3s / 7s），失败直接返回 `blocked`，
   不做无限重试。这台机器用完会关机，地址也变过几次。
4. **密钥不进配置文件、不进日志。** 走 DSH 的 credentials 服务，读时现取不缓存。
5. **`skipMerge` 时不会顺手合并别的分支。** 只发布目标分支当前代码。
6. **Spug 建单显式带主机。** Spug 的建单接口不会自动套用发布配置里的主机，少传就直接报
   「请选择要部署的主机」。插件把发布配置的 `host_ids` 原样传下去；配置里一个主机都没有时，
   当场说明「这个发布配置没配主机」而不是把 Spug 的校验错误抛给用户。

唯一需要确认的情况是**发线上**：`prod` / `线上` 环境要求再调一次并带 `confirmProd=true`。
测试、开发、灰度都是说了就发。

## 连接地址

**插件不自带任何地址。** GitLab、Spug、小程序构建机的地址默认全是空字符串，
第一次使用前必须在面板的「配置」展项里填一次（点标题展开），**输入框失去焦点就保存**，填完立即生效
（这几个字段是 volatile 配置，不会触发插件重启）。

| 设置项 | 说明 |
| --- | --- |
| `gitlabEndpoint` | GitLab 实例地址，到 `/api/v4` 之前那一段 |
| `spugBaseUrl` | Spug 地址（完整 URL，如 `http://host:6060/`） |
| `qqcBaseUrl` | 小程序构建机地址。这台机器用完会关机、地址也变过，所以必须自己填 |

地址没填全时，`yq_release` 会在**发出任何网络请求之前**停下来，返回
`ENDPOINT_NOT_CONFIGURED` 并列出缺哪几项；`yq_release_plan` 也会提示还缺哪些。

注意小程序链路和 Spug 链路用的是不同地址 —— 只发 H5 时 `qqcBaseUrl` 空着也能跑，
但计划里会一直提示这一项没填。

## 凭据

三个值只从 DSH 凭据库读取，**没有任何 `.env` / 环境变量兜底**。

| 名称 | 说明 |
| --- | --- |
| `GITLAB_ACCESS_TOKEN` | GitLab 私有 token |
| `SPUG_USERNAME` | Spug 用户名 |
| `SPUG_PASSWORD` | Spug 密码 |

凭据和地址在同一个「配置」展项里，同样失焦即存。保存后行内只显示 `***`，值不会回传到浏览器。
没填就发起发布会直接停在这一步并说明缺哪一项 —— 不会去读 `gitlab-skill` / `spug-skill` 的 `.env`，
所以别的工具留在磁盘上的密钥不会替用户发版。

> `SPUG_BASE_URL` / `SPUG_USERNAME` / `SPUG_PASSWORD` / `SPUG_IP` / `SPUG_PORT` 这些名字
> 来自 `spug-skill` 的 `.env`。本插件不读那个文件：前三个分别对应面板里的
> `spugBaseUrl` 设置项和 `SPUG_USERNAME` / `SPUG_PASSWORD` 凭据；`SPUG_IP` + `SPUG_PORT`
> 是本插件没有的写法，Spug 地址只填完整 URL 一项。

## 记录

每次发布追加一行到 `~/.dsh/yq-release/releases.jsonl`。

这个账本**从空开始**：插件不导入任何别的工具留下的历史，所以里面每一条记录都意味着
插件自己跑过那次发布。用着用着它会自然长成一份可信的发版历史 —— 哪条分支发到哪、
走的什么链路、commit 是多少、成功还是阻塞。

每条记录带一份 `chain` 快照（链路 id、目标分支、发布方式、应用名、环境）。这份快照就是
上面「链路从哪来」的第二个来源：插件下次启动时从账本把它们还原成可用的链路。

记录同时是**历史事实，不是规则**。它能告诉你「这条分支上次发到哪」，但不会替用户决定这次发哪。

## 通知

插件自己**不发任何推送**：没有飞书 webhook，没有邮件，没有外部回调，代码里也没有这类调用。

发布完成后要收到提醒，用 DSH 自己的完成通知就行 —— 本机 profile 已装 `dsh-notify-me`，
它在 `turn/end` 时提示你回来查看结果。也就是说：发布跑在对话里，通知由 DSH 的事件触发，
插件只负责把结果写进卡片和账本。

小程序构建机那边会自己发飞书（那是构建机 `build.mjs` 的行为，和本插件无关，也关不掉）。

## 配置

服务地址见上面「连接地址」一节（面板「配置」展项里填，默认全空）。除此之外 `Config` 里是超时、轮询间隔
和可选的 `projects` 登记表。

`projects` 默认是空的 —— 不写它就完全靠发布记录长链路。想提前把链路固定下来（比如团队新项目、
或者想用分支名自动认），在这里手写：

```yaml
projects:
  yeqiao-mobile:
    gitlabProject: yeqiao-mobile
    gitlabProjectId: 121
    chains:
      h5:
        detect: h5-          # 写 detect 才能从分支名自动认
        targetBranch: test
        provider: spug
        spugApp: new_h5
        spugEnv: test
```

`config.projects` 里的同名链路优先于记录里学到的：手写的定义永远比推断出来的权威。

## 目录

| 文件 | 作用 |
| --- | --- |
| `lib/index.js` | 宿主入口：装配 service、注册三个工具、注册面板 bridge |
| `lib/config.js` | `Config`、`projects` 登记表、从记录反推链路 |
| `lib/chains.js` | 链路判定与首次发布的显式定义，认不出或认出多条都报错，绝不猜 |
| `lib/release-service.js` | 唯一的发布流程实现，工具与面板共用 |
| `lib/providers/gitlab.js` | GitLab MR 合并 |
| `lib/providers/spug.js` | Spug 登录、发布请求、轮询状态 |
| `lib/providers/qqc.js` | 构建机探活、触发、轮询、从日志取 commit |
| `lib/memory.js` | 追加式发布记录 |
| `lib/client.js` | 侧边栏面板（React）：折叠的配置展项 + 链路、历史记录 |

## 已知限制

- 面板不发起发布，也没有实时进度条：发布在对话里跑，结果由工具卡片呈现。
- 小程序构建机是台会被关掉的机器。连不上时插件只会告诉你「去开机」，不会自己等。
- 构建机的项目别名（`qqc` / `乔乔车` / `car` / `养车`）由构建机自己解析，插件原样透传。
